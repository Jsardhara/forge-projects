# posture

**Five read-only verifiers, one exit code, one transition list.**

This repo ships five tools that all answer a narrow question about this host and all
share the same contract — `0` clean, `1` findings, `2` unmeasurable:

| Verifier | Question |
|---|---|
| `secretsurface` | where does credential-shaped material live, and which copies are live |
| `exitpath` | can funds leave through a venue's withdrawal path right now |
| `kcheck` | is the running kernel in a verified CVE range, and is the attack path on |
| `skillbom` | what authority footprint do the installed skills carry |
| `cvewatch` | has the vendor shipped the fix for a tracked CVE yet |

Until now the only file that knew all five existed was `INDEX.md`. Answering "did
anything transition since yesterday?" took five commands with five flag shapes, a
memory test that fails silently — and a check that is not run is indistinguishable
from a check that passed.

`posture` runs them, keeps a baseline, and prints **only what changed**.

```bash
cd 2026-11-03-posture
PYTHONPATH=src python3 -m posture --diff          # human transition list
PYTHONPATH=src python3 -m posture --diff --json   # machine rollup
PYTHONPATH=src python3 -m posture --only kcheck   # one verifier
```

## Exit contract

| code | meaning |
|---|---|
| `0` | all verifiers clean |
| `1` | at least one verifier has findings — a human should look |
| `2` | **partial**: at least one verifier could not be measured (crash, timeout, exit 2, empty output) |

`2` outranks `1`. A run where four verifiers are fine and one is broken is not a run
with one problem — it is a run with five unknown results, and it must never read as
clean. Fail-closed rules, all covered by tests:

- a traceback is `error`, whatever exit code the process produced;
- exit 1 with **no output** is `error` — that is what a broken launch looks like, not a finding;
- exit 0 with no output at all is `unmeasurable` — nothing was proven;
- any exit code outside 0/1/2 is `error`.

## What a transition is

Per verifier, `posture` stores a status and a digest of the verifier's normalized
stdout. `--diff` reports:

- `status: clean -> findings` — the answer changed;
- `output changed (status still …)` — same verdict, different evidence;
- `appeared` / `vanished` — the set of verifiers moved.

Normalization drops ISO timestamps and durations, because otherwise the digest would
move every morning and "TRANSITION" would mean nothing. Counters that are not
verdicts are registered per verifier in `specs.VOLATILE` — today that is only
`exitpath`'s block heights, which change every block and mean nothing about posture.
If a new verifier's digest flaps while its status does not, register its counter
there rather than ignoring the report.

The first `--diff` run prints `baseline established` and saves the baseline; it does
not fabricate transitions.

## Discovery

A verifier is a dated directory `YYYY-MM-DD-<name>/src/<module>/cli.py` whose name is
in `specs.DEFAULT_SPECS`. Membership is registered deliberately: this repo holds
~40 other dated projects that ship a `cli.py` and are not verifiers. Running them all
would fill every report with `unmeasurable` noise — measured on the real tree, that
was 45 projects and 27 false unmeasurable verdicts from a single run. `--all` opts
them in explicitly; `--only name,name` narrows.

`posture` never runs itself. Without that exclusion the real first run recursed into
its own project and timed out.

## State

Default `~/.local/state/posture/state.json` (override with `--state` or
`POSTURE_STATE`). Verifier-owned files (cvewatch's own state, skillbom's ledger) go
under `verifiers/` beside it. Writes are atomic (temp file + `os.replace`); a corrupt
or missing baseline loads as "no baseline" and never raises.

## Cron shape

```cron
20 6 * * *  cd <repo>/2026-11-03-posture && PYTHONPATH=src python3 -m posture --diff --quiet --json
```

`--quiet` is silent when clean, so anything that arrives is either a transition, a
finding, or a verifier that stopped measuring — the three things worth a human.
`--timeout` (default 120s) bounds each verifier so one hung network fetch cannot hide
the other four results; a timed-out verifier is `unmeasurable`, never clean.

## Scope

Read-only. It never invokes root, never fixes anything, and writes nothing but its own
state. Output ends at "here is what changed" — acting on it stays operator T3/T4.

## Install / test

No install, no dependencies, Python 3.8+ standard library.

```bash
PYTHONPATH=src python3 -m unittest discover -s tests
```

81 tests, 90.5% statement coverage of `src/posture` (`.cover/` is generated by
`python3 -m trace --count --summary --missing --coverdir=.cover`).
